# 접근성 수동/브라우저 자동화 검사 체크리스트 (Task 21.3)

이 문서는 `tests/test_component_accessibility_examples.py`를 포함한 Python 테스트
하네스가 실제 브라우저 DOM·보조 기술 없이는 검증할 수 없는 항목을 모아 둔 체크리스트다.
Requirements 14.3, 14.4, 14.5, 14.9, 14.10을 다루며, 실행은 실제 브라우저(및 필요 시
axe-core 등 자동화 접근성 스캐너)에서 수행해야 한다.

> 이 앱은 빌드 도구 없는 HTML + CSS + 최소 vanilla JavaScript로 구현되어 있으므로(design.md
> 기술 제약), 여기 나열된 항목은 실제 페이지 로드가 필요하다. Python 단위/속성/예제 테스트는
> 서버 응답과 `static/app.js`·`static/app.css`에 필요한 로직/텍스트/클래스가 존재하는지까지만
> 검증한다.

## 1. 키보드 조작·초점 순서 (Requirements 14.3, 14.4)

- [ ] `/` 및 `/results` 진입 시 Tab 키만으로 skip link → 전역 내비게이션 → 본문의 모든
      상호작용 요소(입력창, 버튼, 드롭다운, 상세 토글, 요약 탭, 인용 버튼)에 순서대로 도달하는지 확인한다.
- [ ] 판례 카드의 "상세 보기" 토글을 Enter/Space로 펼치고 접을 수 있는지 확인한다.
- [ ] 응답 본문에서 드래그 없이 키보드만으로(예: Shift+화살표로 텍스트 선택 후 Tab) 문장에
      초점을 이동하고 "현재 문장 재검토" 버튼을 실행할 수 있는지 확인한다.
- [ ] 출처 인용 버튼 클릭 후 전문 뷰어가 열리고 강조된 anchor로 초점이 이동하는지, "돌아가기"
      버튼으로 원래 인용 위치로 초점이 복귀하는지 확인한다(초점 왕복, Requirements 3.14/13.5).
- [ ] 타임라인 이벤트 편집 폼의 각 입력 필드와 "수정 반영" 버튼에 Tab으로 순서대로 도달하는지 확인한다.
- [ ] 보고서 미리보기의 "복사"·"다운로드" 버튼에 키보드로 접근하고 실행할 수 있는지 확인한다.
- [ ] 어떤 상호작용 요소도 키보드 포커스 트랩에 걸리지 않는지 확인한다.

## 2. 초점 가시성 (Requirement 14.4/14.9)

- [ ] 위 모든 상호작용 요소에 키보드로 초점을 이동했을 때 `:focus-visible` 아웃라인이
      배경과 충분한 대비로 보이는지 확인한다(마우스 클릭 시에는 표시되지 않아야 함).
- [ ] Windows 고대비 모드(forced-colors: active)를 활성화한 브라우저에서 배지·카드·탭 등에
      테두리가 유지되는지 확인한다.

## 3. 상태 알림 (`role="status"`/`role="alert"`) (Requirements 14.3, 15.9)

- [ ] 화면 판독기(NVDA/VoiceOver 등)를 사용해 다음이 인터럽트 없이(`status`) 알림되는지 확인한다:
      질의 해석 결과, 세션 상태 복구 안내, 타임라인 수정 상태, 보고서 생성/복사/다운로드 상태.
- [ ] 다음이 인터럽트로(`alert`) 알림되는지 확인한다: HTTP/단계 오류 패널, 음성 인식 실패,
      제출 실패 메시지.
- [ ] 새로고침 시 세션 상태가 없을 때 표시되는 "임시 화면 상태가 초기화되었습니다." 안내가
      화면 판독기에 알림되는지 확인한다.

## 4. 확대(200%)·강제 색상·모션 감소 (Requirement 14.9)

- [ ] 브라우저 확대 200%에서 페이지 전체에 가로 스크롤이 발생하지 않는지 확인한다(뷰포트
      320–1440 CSS px 범위 포함).
- [ ] OS/브라우저의 "모션 감소" 설정을 켠 상태에서 애니메이션/전환이 사실상 즉시 적용되는지 확인한다.

## 5. axe-core 계열 자동화 접근성 스캔 (Requirement 14.5)

- [ ] 실제 브라우저(Playwright/Selenium 등)로 `/`, `/results`, 판례 상세가 펼쳐진 상태,
      선택 재검토 패널이 열린 상태, 오류 패널이 표시된 상태 각각에 대해 axe-core(또는 동등한
      자동화 접근성 스캐너)를 실행하고 심각도 "critical"/"serious" 위반이 0건인지 확인한다.
- [ ] 발견된 "moderate" 이하 위반은 별도 이슈로 기록하고 필요 시 후속 태스크에서 처리한다.

## 참고

- 이 체크리스트의 항목은 CI에서 자동 실행되지 않는다. 브라우저 기반 회귀 테스트 도입 시
  이 문서를 대체하거나 각 항목을 자동화 테스트로 승격할 수 있다.
- 서버 측에서 확인 가능한 대응 항목(고정 문구, 전문 최초 접힘, 요약 탭·전문 독립, 빈 상태,
  배지 색 외 구분, 선택 재검토 두 액션, 출처 초점 왕복 로직, 상급심 변경 강조, 복사/다운로드/
  음성 실패 대안)은 `tests/test_component_accessibility_examples.py`에서 예제 테스트로 검증한다.
