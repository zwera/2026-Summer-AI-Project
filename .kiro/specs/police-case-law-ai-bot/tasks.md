# Implementation Plan: 경찰 판례·법령 AI 봇

## Overview

이 계획은 설계 문서의 계층 경계(표현·애플리케이션·도메인·데이터·로컬 I/O)를 따라 목업 전용, 결정적, 추적 가능한 시연 애플리케이션을 점진적으로 구현한다. 구현 언어는 요구사항 15와 기능 범위에 따라 다음과 같이 고정한다.

- **핵심 애플리케이션·도메인 로직과 서버 측 웹 계층: Python** (`Python_기준_구현`, `Python_웹_서버`)
- **클라이언트 웹 계층: HTML + CSS + 최소 JavaScript** (표현·상호작용만, 법률 로직 재계산 금지)
- **속성 기반 테스트(PBT): 성숙한 Python PBT 라이브러리(Hypothesis 권장)** — 각 속성은 정확히 하나의 property test로 구현하고 최소 100회 실행하며, 실패 시 seed·경로·축소된 최소 반례 등 재현 정보를 보존한다.

설계의 TypeScript 시그니처는 계약 의사코드이므로, 아래 모든 도메인·서버 태스크는 동일한 계약을 Python으로 구현한다. 각 태스크는 이전 태스크 위에 쌓이며 마지막에 서버·클라이언트 배선까지 연결해 고립 코드를 남기지 않는다.

주의: 목업 동작을 위해 검색 엔진·임베딩·벡터 DB·외부 판례/법령 API·원격 음성 인식·실제 LLM을 위한 클라이언트/어댑터/포트를 구현하거나 주입하지 않는다. 이런 의존성은 테스트에서 가짜 구현으로 대체할 숨은 의존성도 아니다.

## Notes

- `*` 표시 sub-task는 선택(테스트) 태스크이며 빠른 MVP에서 생략할 수 있다. 핵심 구현 sub-task는 생략하지 않는다.
- 각 태스크는 특정 요구사항 조항을 참조하며, 각 속성 테스트는 설계의 특정 Correctness Property와 검증 대상 요구사항을 명시한다.
- 모든 속성 테스트는 성숙한 Python PBT 라이브러리로 최소 100회 실행하고, 실패 시 seed·경로·축소된 최소 반례를 보존한다. 오류 속성은 유효 데이터셋에 한 종류의 mutation만 적용해 원인을 분리하고, 실제 시연 fixture와 독립적인 단순 참조 오라클을 사용한다.
- 도메인 함수는 현재 시각·난수·로케일 의존 정렬을 사용하지 않으며 날짜 기준은 `dataset.asOfDate`, 최종 동순위 키는 정규화된 `caseId`다.
- 검색 엔진·임베딩·벡터 DB·외부 판례/법령 API·원격 음성 인식·실제 LLM을 위한 코드·포트·어댑터·mock server는 추가하지 않는다.
- 체크포인트는 데이터·해석 계층(태스크 4), 도메인 계층(태스크 14), 전체(태스크 23)에서 점진적 검증을 보장한다.
