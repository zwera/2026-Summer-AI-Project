# Requirements Document

## Introduction

경찰 판례·법령 AI 봇은 법률 전문가 중심의 키워드 검색 서비스와 달리, 현장 경찰 실무자가 일상적인 현장 표현으로 사건 상황을 설명하면 의사결정과 보고서 작성에 참고할 판례 및 법령 정보를 탐색하고 이해하도록 돕는 시연용 웹 애플리케이션이다. 사용자는 정확한 사건번호, 죄명 또는 법률 용어를 알지 못해도 표준 데스크톱·모바일 웹 브라우저에서 상황 중심으로 질의할 수 있다.

현재 범위는 실제 법률 검색 서비스가 아니라 **사전에 정의된 가상·샘플 데이터로 검색, 근거 제시, 답변 및 화면 상호작용을 모사하는 웹 배포형 목업(mockup)** 이다. 핵심 애플리케이션·도메인 로직과 서버 측 웹 계층은 Python으로 구현하고, 목업 데이터와 정적 자산은 서버 배포물에 포함한다. 공개 또는 지정된 웹 호스팅 환경에 배포하더라도 모든 법률 관련 결과는 사전 정의 데이터에서 결정적으로 제공되며, 웹 배포를 운영형 RAG나 외부 법률 데이터 연동으로 확대하지 않는다. 모든 결과는 법률 자문, 법률 판단 또는 업무 적용을 위한 정확성 보증 자료가 아니다.

### 현재 범위에서 제외되는 항목

- 운영용 검색 엔진, 임베딩 생성 및 벡터 데이터베이스 구축
- 외부 판례·법령 API 연동, 외부 데이터 수집 및 실시간 법령 동기화
- 실제 생성형 모델, 외부 LLM 및 실제 또는 원격 음성 인식 처리
- 판례·법령 최신성 보증과 운영형 RAG 또는 실제 법률 데이터 서비스 제공
- 실제 법률 자문, 법률 판단, 수사 지휘 및 법적 정확성 보증
- 사용자 계정, 애플리케이션 자체 인증 및 사용자별 권한 관리
- 상황 질의, 선택 문구, 보고서 본문의 영구 저장과 사용자별 이력 관리
- 특정 Python 웹 프레임워크의 확정; 프레임워크 선택은 설계 단계에서 수행한다

## Glossary

- **경찰_판례_AI_봇**: 이 문서에서 정의하는 경찰 실무자용 판례·법령 탐색 및 설명 시연 시스템.
- **사용자**: 경찰 현장 업무, 수사 업무 또는 보고서 작성 업무를 수행하며 경찰_판례_AI_봇을 이용하는 경찰 실무자.
- **웹_애플리케이션**: 사용자가 별도 네이티브 애플리케이션 설치 없이 웹 브라우저로 접속하고 HTTP(S) 요청·응답으로 이용하는 애플리케이션.
- **표준_웹_브라우저**: 표준 HTML, CSS, JavaScript 및 HTTP(S)를 지원하는 데스크톱 또는 모바일 웹 브라우저.
- **최신_주요_브라우저**: 배포 검증일에 각 공급자가 제공하는 최신 안정 주 버전의 데스크톱 Chrome, Edge, Firefox, Safari와 모바일 Chrome, Safari.
- **Python**: 핵심 애플리케이션·도메인 로직과 서버 측 웹 계층의 구현에 사용하는 프로그래밍 언어.
- **Python_웹_서버**: Python으로 구현되어 브라우저 요청을 검증하고 목업_RAG 및 화면 데이터 처리 결과를 HTTP(S) 응답으로 반환하는 서버 측 시스템.
- **서버_측_웹_계층**: HTTP(S) 라우팅, 요청 검증, 세션 범위 처리, 응답 생성 및 정적 자산 제공을 담당하는 Python_웹_서버 계층.
- **핵심_애플리케이션_및_도메인_로직**: 상황_질의 해석, 목업_RAG 단계 제어, 목업_데이터셋 검증, 매칭, 정렬, 분류, 근거 판정 및 보고서용_사실관계 생성을 결정하는 로직.
- **Python_기준_구현**: 핵심_애플리케이션_및_도메인_로직의 기대 결과를 결정하는 권위 있는 Python 구현.
- **클라이언트_웹_계층**: HTML과 CSS로 화면을 표현하고 필요한 최소 JavaScript로 사용자 상호작용, 화면 상태 및 웹_앱_통신을 처리하는 브라우저 측 계층.
- **HTTP(S)**: 웹_애플리케이션의 브라우저와 Python_웹_서버 사이에서 요청과 응답을 교환하는 HTTP 또는 암호화된 HTTPS 통신 방식.
- **웹_앱_통신**: 사용자의 브라우저와 동일한 경찰_판례_AI_봇 배포의 Python_웹_서버 사이에서 이루어지는 HTTP(S) 요청·응답과 정적_자산 전송.
- **서버_배포물**: Python 소스 또는 실행 패키지, 목업_데이터셋, 템플릿 및 정적_자산을 함께 포함하여 호스팅 환경에 배포하는 산출물.
- **정적_자산**: 서버_배포물에 포함되어 브라우저에 제공되는 HTML, CSS, JavaScript, 이미지, 아이콘 및 글꼴 파일.
- **웹_호스팅_환경**: 공개 인터넷에서 접근 가능한 호스팅 환경 또는 배포 주체가 지정한 네트워크·호스트 범위에서 접근 가능한 Python 지원 호스팅 환경.
- **운영_배포**: 개발자 개인용 실행을 넘어 실제 사용자가 웹_호스팅_환경의 URL로 접속하도록 제공하는 배포 상태.
- **직접_URL_접속**: 사용자가 이전 화면 탐색 없이 웹_애플리케이션의 URL을 브라우저 주소창에 입력하거나 링크로 여는 행위.
- **브라우저_세션**: 사용자가 하나의 브라우저 탭 또는 창에서 웹_애플리케이션에 접속한 시점부터 해당 탭·창을 닫거나 세션 유효 시간이 끝날 때까지의 임시 상호작용 범위.
- **반응형_UI**: 320 CSS 픽셀 이상 1440 CSS 픽셀 이하의 뷰포트 너비에서 핵심 입력, 탐색, 결과, 고지 및 작업 기능을 페이지 수준 가로 스크롤 없이 제공하는 화면 구성. 줄바꿈할 수 없는 사건번호 또는 목업_출처 원문은 해당 콘텐츠 영역 내부에서 줄바꿈 또는 스크롤할 수 있다.
- **환경별_설정**: 공개 URL, 호스트, 포트, HTTPS 적용 여부 및 실행 모드처럼 배포 환경에 따라 달라지며 Python_웹_서버가 서버 측 환경변수에서 읽는 설정값.
- **비밀값**: 인증 자격 증명, API 키, 접근 토큰, 암호화 키 또는 외부에 공개되면 안 되는 설정값.
- **민감_사용자_콘텐츠**: 사용자가 입력한 원문 상황_질의, 선택_재검토의 선택 문구 및 보고서용_사실관계 본문.
- **영구_저장**: 브라우저_세션 종료 또는 Python_웹_서버 재시작 후에도 내용을 복구할 수 있도록 파일, 데이터베이스 또는 브라우저 영속 저장소에 기록하는 행위.
- **외부_분석_전송**: 민감_사용자_콘텐츠를 원격 분석, 원격 계측, 광고 또는 사용자 행동 추적 서비스로 전송하는 행위.
- **애플리케이션_로그**: Python_웹_서버 또는 웹_애플리케이션이 진단과 운영 상태 확인을 위해 기록하는 요청, 응답 및 오류 정보.
- **안전_오류_응답**: HTTP 오류 상태와 일반화된 오류 안내를 제공하되 내부 예외 상세, 비밀값, 민감_사용자_콘텐츠, 목업_데이터_레코드에 없는 법률 내용 또는 대체 법률 결론을 포함하지 않는 응답 또는 오류 화면.
- **공개_배포_고지문**: `이 웹 애플리케이션은 수사 및 법률 업무의 정보 정리·검토를 지원하기 위한 시연용 프로토타입입니다. 제공되는 데이터와 결과는 사전 정의된 목업 데이터에 기반하며, 실제 사건의 최종 법률 판단·수사 판단 또는 공식 업무 결정을 대체하지 않습니다. 실제 업무 적용 시에는 관계 법령, 내부 절차 및 담당 전문가의 검토가 필요합니다.`라는 문구.
- **결정적_결과**: 동일한 목업_데이터셋과 동일한 입력에 대해 사용자, 브라우저_세션 또는 Python_웹_서버 재시작 여부와 관계없이 동일한 단계, 매칭, 정렬, 분류, 근거, 응답 및 보고서 결과를 반환하는 성질.
- **Python_지원_호스팅**: 선언된 Python 런타임과 고정된 애플리케이션 의존성을 실행하고 환경별_설정을 주입하며 HTTP(S) 요청을 수신할 수 있는 웹 호스팅 환경.
- **진입_화면**: 사용자가 직접_URL_접속으로 처음 확인하는 목업 범위, 고지 및 상황 입력 시작 화면.
- **결과_화면**: 목업_검색 결과, 목업_응답, 판례·법조문 정보 또는 보고서용_사실관계를 표시하는 화면.
- **제3자_공유**: 민감_사용자_콘텐츠를 경찰_판례_AI_봇의 현재 사용자와 서버 처리 경계 밖의 개인, 조직 또는 서비스에 제공하는 행위.
- **HTTP_클라이언트_오류**: 잘못된 요청 구문·본문·메서드·콘텐츠 유형 또는 존재하지 않는 URL에 대해 400 이상 499 이하 상태 코드로 반환하는 오류.
- **HTTP_서버_오류**: 유효한 요청을 Python_웹_서버 내부 오류 또는 목업_데이터셋 가용성 문제로 완료하지 못해 500 이상 599 이하 상태 코드로 반환하는 오류.
- **상황_질의**: 사건번호나 죄명 대신 현장에서 발생한 사람, 행위, 순서, 조건 및 결과를 자연어로 설명한 입력.
- **경찰_현장_표현**: 사용자가 현장에서 통상 사용하는 비법률적 단어 또는 문장.
- **법률_검색어**: 경찰_현장_표현을 판례·법령 탐색에 적합한 법률 용어로 대응시킨 검색 표현.
- **목업_RAG**: 실제 검색·임베딩·벡터 데이터베이스·외부 API·생성형 모델 없이 입력, 검색, 근거 제시 및 응답 흐름만 모사하는 Retrieval-Augmented Generation 시연 기능.
- **목업_RAG_단계**: 입력, 목업_검색, 근거_제시 및 응답으로 구성되며 이 순서로만 진행되는 목업_RAG의 상태.
- **목업_데이터셋**: 시연을 위해 사전에 정의한 가상 또는 샘플 판례, 법조문, 질의, 답변, 출처, 유사도 및 날짜 메타데이터의 집합.
- **목업_데이터_레코드**: 목업_데이터셋 안에서 고유 식별자로 구분되는 사전 정의 판례, 법조문, 질의, 답변, 출처, 유사도, 날짜 또는 화면 상태 기록.
- **목업_fixture**: 서버_배포물에 포함되어 목업_데이터셋을 구성하는 정적 JSON 또는 Python 데이터 레코드.
- **법률_관련_표시값**: 판례, 법조문, 목업_출처, 목업_응답, 요약, 분류, 점수, 경고, 재판 결과, 법령 상태 및 보고서에 연결된 판례_쟁점·출처_식별자처럼 법률 결과를 나타내는 값. 원문 상황_질의, 선택 문구, 사용자가 수정한 사실관계_타임라인 및 보고서용_사실관계 본문은 법률_관련_표시값에 포함되지 않는다.
- **픽스처_출처정보**: 하나의 법률_관련_표시값을 해당 값의 근거가 되는 목업_데이터_레코드 식별자와 직접 근거가 존재하는 경우의 목업_출처 식별자로 추적할 수 있게 하는 정보.
- **레코드_격리**: 유효하지 않은 목업_데이터_레코드 또는 참조만 결과에서 제외하고, 유효한 다른 레코드와 오류 발생 전 화면 상태를 유지하면서 데이터 오류를 표시하는 처리.
- **데이터셋_가용성_실패**: 목업_fixture를 로드할 수 없거나 레코드_격리 후에도 필수 최상위 구조와 참조 무결성을 검증할 수 없어 목업_RAG를 안전하게 실행할 수 없는 상태.
- **정규_결론**: 동일 판례의 법원_결론, 적법성_상태, 해당_심급_인정_죄명 및 해당_심급_재판_결과로 구성되는 변경 불가 결론 집합.
- **위험_판정_축**: 개인_책임_위험을 구성하는 민사 국가배상, 형사 직권남용, 형사 독직폭행 및 징계의 네 판정 축.
- **유효한_선택_영역**: 현재 결과 화면의 목업_응답 안에서 선택되었으며 공백 문자가 아닌 문자를 하나 이상 포함하는 연속 텍스트 범위.
- **사전_정의_음성_시연**: 실제 음성을 인식하지 않고 목업_데이터_레코드에 미리 저장된 음성 시연 항목과 인식 텍스트의 대응을 재생하는 입력 시연.
- **실제_음성_인식**: 사용자의 마이크 입력이나 업로드된 음성에서 인식 텍스트를 생성하는 로컬 또는 원격 처리.

- **오류_전_상태**: 오류 발생 직전에 유지되던 상황_질의, 선택 판례, 요약_단계, 보조_필터 및 선택 문구의 조합.

## Requirements

### 요구사항 1: 목업 RAG 범위와 법률 안전 고지

**사용자 스토리:** 시연 참여자로서, 모든 검색과 답변이 목업 데이터에 기반함을 분명히 알고 싶다. 이를 통해 실제 법률 판단 또는 운영 서비스로 오인하지 않을 수 있다.

#### 인수 기준

1. THE 경찰_판례_AI_봇 SHALL 목업_RAG의 현재 구현 범위를 목업_데이터셋을 이용한 입력, 목업_검색, 근거_제시 및 응답 흐름의 모사로 제한한다.
2. THE Python_기준_구현 SHALL 각 법률_관련_표시값을 사전에 정의된 목업_데이터_레코드만을 근거로 산출하고 해당 값에 픽스처_출처정보를 연결한다.
3. WHEN 경찰_판례_AI_봇이 지원_목업_질의를 수락하면, THE Python_기준_구현 SHALL 목업_RAG_단계를 입력, 목업_검색, 근거_제시, 응답 순서로 진행한다.
4. WHEN 입력, 목업_검색 또는 근거_제시 목업_RAG_단계가 완료되면, THE Python_기준_구현 SHALL 완료된 목업_RAG_단계의 바로 다음 단계만 활성화한다.
5. WHILE 웹_앱_통신이 가능하고 금지된_외부_RAG_AI_법률_데이터_서비스_호출 대상에 대한 연결이 차단된 상태에서, THE 경찰_판례_AI_봇 SHALL 지원_목업_질의에 대한 목업_RAG 흐름을 서버_배포물의 목업_데이터셋만으로 완료한다.
6. THE 클라이언트_웹_계층 SHALL 검색 결과와 목업_응답의 화면 내 가시 영역에 `목업 응답` 표지를 표시한다.
7. WHEN 목업_응답, 목업_출처 또는 보고서용_사실관계가 화면 표시, 복사 또는 내보내기 방식으로 제공되면, THE 클라이언트_웹_계층 SHALL 법률_안전_고지문을 결과와 함께 제공한다.
8. THE 클라이언트_웹_계층 SHALL 데이터_기준일과 `실시간 판례·법령 동기화 없음` 문구를 결과 화면에 표시한다.
9. IF 목업_데이터_레코드가 목업_응답의 주장을 뒷받침하지 못하면, THEN THE Python_기준_구현 SHALL 목업_응답의 주장을 근거_부족으로 분류한다.
10. THE 경찰_판례_AI_봇 SHALL 상황_질의 수신부터 목업_RAG 완료 또는 실패까지 금지된_외부_RAG_AI_법률_데이터_서비스_호출 수를 0건으로 유지한다.
11. WHEN 사용자가 웹 브라우저에서 상황_질의 또는 화면 작업을 제출하면, THE Python_웹_서버 SHALL 동일한 경찰_판례_AI_봇 배포 안의 웹_앱_통신으로 요청을 처리하고 HTTP(S) 응답을 반환한다.
12. THE 경찰_판례_AI_봇 SHALL 웹_앱_통신과 서버_배포물의 정적_자산 전송을 금지된_외부_RAG_AI_법률_데이터_서비스_호출 수에서 제외한다.

### 요구사항 2: 자연어 상황 질의와 법률 용어 변환

**사용자 스토리:** 경찰 실무자로서, 정확한 사건번호나 죄명을 모르더라도 현장 상황을 평소 표현으로 입력하고 싶다. 이를 통해 관련 판례와 법조문을 찾을 수 있다.

#### 인수 기준

1. WHEN 사용자가 사건번호와 죄명이 없는 상황_질의를 제출하면, THE Python_기준_구현 SHALL 상황_질의의 지원_목업_질의 해당 여부를 결정한다.
2. WHEN Python_기준_구현이 상황_질의를 지원_목업_질의로 결정하면, THE Python_기준_구현 SHALL 지원_목업_질의에 사전 연결된 판례 및 법조문 매칭_결과_집합을 반환한다.
3. WHEN 지원_목업_질의에 경찰_현장_표현이 포함되면, THE Python_기준_구현 SHALL 목업_데이터_레코드에 정의된 대응 관계에 따라 경찰_현장_표현을 법률_검색어로 변환한다.
4. WHEN 법률_검색어 변환이 완료되면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 원래 경찰_현장_표현과 법률_검색어의 대응 관계를 변경 없이 함께 표시한다.
5. WHEN 경찰_현장_표현이 법률_검색어로 변환되면, THE Python_기준_구현 SHALL 사람과 행위의 관계, 행위와 시점의 관계, 부정 표현과 부정 대상의 관계를 변환 전과 동일하게 유지한다.
6. IF 상황_질의가 비어 있거나 공백 문자로만 구성되면, THEN THE Python_기준_구현 SHALL 목업_RAG_단계를 입력 상태로 유지한다.
7. WHILE 상황_질의가 비어 있거나 공백 문자로만 구성된 상태에서, THE Python_기준_구현 SHALL 매칭_결과_집합을 빈 집합으로 유지한다.
8. WHEN 비어 있거나 공백 문자로만 구성된 상황_질의가 입력 단계에 유지되면, THE 클라이언트_웹_계층 SHALL 상황 입력 요청을 표시한다.
9. IF 상황_질의가 지원_목업_질의의 핵심 사실과 대응하지만 하나 이상의 표현이 목업_데이터셋의 정의어와 대응하지 않으면, THEN THE Python_기준_구현 SHALL 대응하지 않는 표현을 원문과 함께 `해석 확인 필요`로 분류한다.
10. IF 법률_검색어 변환 결과가 사람, 행위, 시점 또는 부정 표현의 관계를 하나로 보존할 수 없으면, THEN THE Python_기준_구현 SHALL 변환 결과를 `해석 확인 필요`로 분류한다.
11. WHILE 상황_질의 해석 또는 법률_검색어 변환 결과가 `해석 확인 필요` 상태이면, THE Python_기준_구현 SHALL 목업_RAG_단계를 입력 상태로 유지한다.
12. WHILE 상황_질의 해석 또는 법률_검색어 변환 결과가 `해석 확인 필요` 상태이면, THE Python_기준_구현 SHALL 매칭_결과_집합을 빈 집합으로 유지한다.
13. WHEN 상황_질의 해석 또는 법률_검색어 변환 결과가 `해석 확인 필요` 상태이면, THE 클라이언트_웹_계층 SHALL 원문 표현과 해석 확인 요청을 표시한다.
14. IF 상황_질의의 핵심 사실이 목업_데이터셋의 모든 지원_목업_질의와 대응하지 않으면, THEN THE Python_기준_구현 SHALL 목업_RAG_단계를 입력 상태로 유지한다.
15. WHEN Python_기준_구현이 상황_질의를 지원_목업_질의 범위 밖으로 결정하면, THE 클라이언트_웹_계층 SHALL `목업에서 지원하지 않는 질의`라는 안내와 Python_기준_구현이 반환한 지원 경찰_직무_시나리오 목록을 표시한다.
16. WHILE 상황_질의가 지원_목업_질의 범위를 벗어난 상태에서, THE Python_기준_구현 SHALL 매칭_결과_집합을 빈 집합으로 유지한다.
17. WHEN 동일한 상황_질의와 동일한 목업_데이터셋이 반복 사용되면, THE Python_기준_구현 SHALL 동일한 지원 여부, 법률_검색어 집합, 대응 관계 및 매칭_결과_집합을 반환한다.
18. WHEN 클라이언트_웹_계층이 질의 해석 결과를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 지원 여부, 대응 관계 및 관계 보존 결과를 재해석하지 않고 표시한다.

### 요구사항 3: 판례·법조문 매칭과 출처 열람

**사용자 스토리:** 경찰 실무자로서, 질의와 관련된 판례 및 법조문을 한 화면에서 확인하고 싶다. 이를 통해 답변의 근거를 원문과 대조할 수 있다.

#### 인수 기준

1. WHEN 지원_목업_질의의 목업_검색이 완료되면, THE Python_웹_서버 SHALL 판례 식별자 집합, 법조문 식별자 집합 및 직접 근거 출처_식별자 집합을 응답으로 반환한다.
2. WHEN 클라이언트_웹_계층이 목업_검색 응답을 수신하면, THE 클라이언트_웹_계층 SHALL Python_웹_서버가 반환한 판례 식별자 집합의 각 판례를 누락과 추가 없이 정확히 한 번 표시한다.
3. WHEN 클라이언트_웹_계층이 목업_검색 응답을 수신하면, THE 클라이언트_웹_계층 SHALL Python_웹_서버가 반환한 법조문 식별자 집합의 각 법조문을 누락과 추가 없이 정확히 한 번 표시한다.
4. WHEN 클라이언트_웹_계층이 목업_응답을 표시하면, THE 클라이언트_웹_계층 SHALL Python_웹_서버가 각 인용 문장에 반환한 직접 근거 출처_식별자 집합을 누락, 추가 및 중복 없이 표시한다.
5. THE 클라이언트_웹_계층 SHALL 각 판례 결과에 Python_웹_서버가 반환한 사건번호, 법원명, 심급, 선고일 및 경찰_직무_시나리오를 표시한다.
6. THE 클라이언트_웹_계층 SHALL 각 판례 결과에 Python_웹_서버가 반환한 유사도_점수, 적법성_상태 및 법령_기준_상태를 표시한다.
7. THE 클라이언트_웹_계층 SHALL 각 법조문 결과에 Python_웹_서버가 반환한 법령명, 조·항·호 및 시행일을 표시한다.
8. WHEN 판례 결과가 처음 표시되면, THE 클라이언트_웹_계층 SHALL 전문을 접힌 상태로 제공한다.
9. WHEN 사용자가 접힌 전문을 펼치면, THE 클라이언트_웹_계층 SHALL Python_웹_서버가 선택 판례에 반환한 각 목업_출처 레코드를 누락, 추가 및 중복 없이 정확히 한 번 표시한다.
10. WHEN 사용자가 출처_식별자를 선택하면, THE 클라이언트_웹_계층 SHALL 선택한 출처_식별자가 가리키는 전문 내 근거 구절의 위치로 이동한다.
11. WHEN 출처_식별자가 가리키는 근거 구절이 화면에 표시되면, THE 클라이언트_웹_계층 SHALL 인용 문장의 직접 근거 구절을 강조한다.
12. IF Python_웹_서버가 반환한 판례 식별자 집합 또는 법조문 식별자 집합이 비어 있으면, THEN THE 클라이언트_웹_계층 SHALL 비어 있는 결과 유형에 `일치하는 목업 자료 없음` 상태를 표시한다.
13. IF 출처_식별자가 목업_출처 레코드와 연결되지 않거나 선택 판례에 속하지 않으면, THEN THE 경찰_판례_AI_봇 SHALL 유효하지 않은 참조에 레코드_격리를 적용하고 `출처 데이터 오류`를 표시한다.
14. WHILE 유효하지 않은 출처 참조가 레코드_격리된 상태에서, THE 클라이언트_웹_계층 SHALL Python_웹_서버가 반환한 나머지 유효한 판례, 법조문 및 목업_출처를 유지한다.

### 요구사항 4: 경찰 직무 시나리오 분류와 적법·위법 비교

**사용자 스토리:** 경찰 실무자로서, 형사·민사·행정 분류보다 실제 경찰 행위별로 판례를 탐색하고 싶다. 이를 통해 유사한 현장 조치의 적법 사례와 위법 사례를 비교할 수 있다.

#### 인수 기준

1. THE 경찰_판례_AI_봇 SHALL 현행범체포, 임의동행, 긴급체포, 압수수색, 미란다 원칙 고지, 진술거부권, 가정폭력 초동조치 및 음주단속을 경찰_직무_시나리오 탐색 항목으로 제공한다.
2. THE 경찰_판례_AI_봇 SHALL 경찰_직무_시나리오를 판례 탐색의 기본 분류로 사용한다.
3. THE Python_기준_구현 SHALL 목업_데이터셋의 각 판례를 하나 이상의 경찰_직무_시나리오로 분류한다.
4. THE Python_기준_구현 SHALL 각 판례의 적법성_상태를 적법, 위법 또는 판단_혼재 중 정확히 하나로 분류한다.
5. WHEN 클라이언트_웹_계층이 경찰_직무_시나리오 또는 적법성_상태를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 분류를 재분류하지 않고 표시한다.
6. WHEN 사용자가 경찰_직무_시나리오를 선택하면, THE Python_기준_구현 SHALL 선택한 경찰_직무_시나리오의 판례를 적법, 위법 및 판단_혼재의 세 집합으로 분할하여 반환한다.
7. WHEN 경찰_직무_시나리오 비교 화면이 표시되면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 선택한 경찰_직무_시나리오에 반환한 모든 판례를 세 구분 영역 전체에 누락 없이 표시한다.
8. WHEN 경찰_직무_시나리오 비교 화면이 표시되면, THE 클라이언트_웹_계층 SHALL 각 판례를 적법성_상태와 일치하는 하나의 구분 영역에 정확히 한 번 표시한다.
9. THE 경찰_판례_AI_봇 SHALL 각 경찰_직무_시나리오에 적법 판례 한 건 이상과 위법 판례 한 건 이상을 목업_데이터_레코드로 제공한다.
10. WHEN 판단_혼재 판례가 표시되면, THE 클라이언트_웹_계층 SHALL 판례 안의 각 경찰 행위와 각 경찰 행위에 대응하는 법원 판단을 별도 항목으로 표시한다.
11. WHERE 전통적 사건 분야 정보가 목업_데이터셋에 포함된 경우, THE 경찰_판례_AI_봇 SHALL 형사, 민사 및 행정 정보를 보조_필터로 제공한다.
12. WHEN 사용자가 경찰_직무_시나리오와 보조_필터를 함께 선택하면, THE Python_기준_구현 SHALL 두 선택 조건을 모두 충족하는 판례의 교집합만 반환한다.
13. WHEN 클라이언트_웹_계층이 경찰_직무_시나리오와 보조_필터의 결합 결과를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 교집합의 판례를 재분류 또는 추가 필터링하지 않고 표시한다.

### 요구사항 5: 단계별 판례 요약과 실무 언어 설명

**사용자 스토리:** 경찰 실무자로서, 시간과 업무 목적에 맞는 길이로 판례를 이해하고 싶다. 이를 통해 핵심 판단을 빠르게 파악한 뒤 필요한 경우 상세 내용과 원문을 확인할 수 있다.

#### 인수 기준

1. THE 경찰_판례_AI_봇 SHALL 각 판례에 3줄_요약, 10줄_요약 및 상세_요약 선택 항목을 제공한다.
2. WHEN 사용자가 3줄_요약을 선택하면, THE Python_기준_구현 SHALL 사건 개요, 법원_결론 및 현장 경찰 핵심 포인트를 순서대로 한 줄씩 포함하는 총 3개의 내용 줄을 반환한다.
3. WHEN 사용자가 10줄_요약을 선택하면, THE Python_기준_구현 SHALL 사건 개요, 주요 사실관계, 판례_쟁점, 법원_결론, 적용 법조문, 해당_심급_인정_죄명, 해당_심급_재판_결과 및 현장 경찰 핵심 포인트를 식별 가능한 항목명과 함께 총 10개의 내용 줄로 반환한다.
4. WHEN 사용자가 상세_요약을 선택하면, THE Python_기준_구현 SHALL 사건 개요, 주요 사실관계, 판례_쟁점, 법원_결론, 적용 법조문, 해당_심급_인정_죄명, 해당_심급_재판_결과 및 현장 경찰 핵심 포인트를 구분된 의미 항목으로 반환한다.
5. THE Python_기준_구현 SHALL 각 요약에서 법률 문구의 의미를 목업_데이터_레코드에 사전 정의된 경찰 현장 표현으로 설명한다.
6. WHEN 요약에서 법률 용어를 경찰 현장 표현으로 설명하면, THE Python_기준_구현 SHALL 설명 대상 법률 용어를 최초 설명 위치에 함께 반환한다.
7. WHEN 동일 판례의 요약_단계가 변경되면, THE Python_기준_구현 SHALL 정규_결론을 변경 전 요약_단계와 동일하게 유지한다.
8. THE Python_기준_구현 SHALL 각 요약의 법원_결론과 현장 경찰 핵심 포인트에 직접 근거가 되는 출처_식별자를 연결한다.
9. IF 목업_출처에 요약 항목의 근거가 없으면, THEN THE Python_기준_구현 SHALL 근거가 없는 요약 항목을 `근거 정보 없음`으로 반환한다.
10. WHEN 사용자가 전문 보기 항목을 선택하면, THE 클라이언트_웹_계층 SHALL 요약_단계와 분리된 접이식 영역에 전문을 표시한다.
11. WHEN 클라이언트_웹_계층이 요약을 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 의미 항목, 내용 줄, 정규_결론 및 출처_식별자를 변경, 재요약, 누락 또는 추가 없이 표시한다.

### 요구사항 6: 경찰관 개인 책임 위험과 행동 배지

**사용자 스토리:** 경찰 실무자로서, 판례가 경찰관 개인의 민사·형사·징계 위험에 주는 의미를 명확히 보고 싶다. 이를 통해 문제가 된 행동과 적법하다고 인정된 행동을 구분할 수 있다.

#### 인수 기준

1. THE Python_기준_구현 SHALL 각 판례의 민사 국가배상, 형사 직권남용, 형사 독직폭행 및 징계 위험_판정_축을 서로 구분하여 판정한다.
2. THE Python_기준_구현 SHALL 민사 국가배상 위험_판정_축을 국가배상 인정, 국가배상 기각, 정보_없음 또는 분류_불가 중 정확히 하나로 판정한다.
3. THE Python_기준_구현 SHALL 형사 직권남용 위험_판정_축을 해당, 불해당, 정보_없음 또는 분류_불가 중 정확히 하나로 판정한다.
4. THE Python_기준_구현 SHALL 형사 독직폭행 위험_판정_축을 해당, 불해당, 정보_없음 또는 분류_불가 중 정확히 하나로 판정한다.
5. THE Python_기준_구현 SHALL 징계 위험_판정_축을 징계 인정, 징계 불인정, 정보_없음 또는 분류_불가 중 정확히 하나로 판정한다.
6. WHEN Python_기준_구현이 위험_판정_축을 판정하면, THE Python_기준_구현 SHALL 해당 위험_판정_축에 연결된 목업_출처 집합 전체를 판정에 사용한다.
7. WHEN Python_기준_구현이 정보_없음 이외의 위험_판정_축 상태를 반환하면, THE Python_기준_구현 SHALL 위험_판정_축 상태의 판정에 사용한 출처_식별자 집합을 함께 반환한다.
8. IF 위험_판정_축을 판단할 목업_출처가 없으면, THEN THE Python_기준_구현 SHALL 해당 위험_판정_축을 정보_없음으로 판정한다.
9. IF 위험_판정_축의 목업_출처가 서로 충돌하거나 하나의 상태를 결정할 수 없으면, THEN THE Python_기준_구현 SHALL 해당 위험_판정_축을 분류_불가로 판정한다.
10. WHEN 경찰 행동을 판단하는 목업_출처가 하나 이상 존재하고 목업_출처 집합 전체가 경찰 행동을 문제로 판단하면, THE Python_기준_구현 SHALL 경찰 행동을 문제_행동 배지로 판정하고 출처_식별자 집합을 연결한다.
11. WHEN 경찰 행동을 판단하는 목업_출처가 하나 이상 존재하고 목업_출처 집합 전체가 경찰 행동을 적법하다고 판단하면, THE Python_기준_구현 SHALL 경찰 행동을 적법_행동 배지로 판정하고 출처_식별자 집합을 연결한다.
12. IF 경찰 행동을 판단할 목업_출처가 없으면, THEN THE Python_기준_구현 SHALL 경찰 행동의 행동_배지_상태를 정보_없음으로 판정한다.
13. IF 경찰 행동에 관한 목업_출처가 서로 충돌하거나 적법과 문제 중 하나로 분류할 수 없으면, THEN THE Python_기준_구현 SHALL 경찰 행동의 행동_배지_상태를 분류_불가로 판정한다.
14. THE Python_기준_구현 SHALL 하나의 경찰 행동을 문제_행동, 적법_행동, 정보_없음 또는 분류_불가 중 정확히 하나의 행동_배지_상태로 판정한다.
15. THE 클라이언트_웹_계층 SHALL 문제_행동 배지와 적법_행동 배지를 색상, 배지 문구 및 아이콘으로 구분한다.
16. WHEN 클라이언트_웹_계층이 위험_판정_축 또는 행동_배지_상태를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 상태와 출처_식별자 집합을 재분류, 누락 또는 추가 없이 표시한다.

### 요구사항 7: 유사도, 검색 우선순위 및 재판 결과

**사용자 스토리:** 경찰 실무자로서, 어떤 판례가 입력 상황과 더 가까운지와 실제 재판 결과가 무엇인지 알고 싶다. 이를 통해 먼저 검토할 판례를 정할 수 있다.

#### 인수 기준

1. THE Python_기준_구현 SHALL 모든 유효한 판례 결과의 유사도_점수를 0 이상 100 이하의 백분율로 반환한다.
2. THE Python_기준_구현 SHALL 각 판례 결과에 목업_데이터_레코드에 사전 정의된 유사도_점수를 재계산 없이 반환한다.
3. THE Python_기준_구현 SHALL 판례 결과를 목업_데이터_레코드에 사전 정의된 검색_우선순위로 정렬하여 반환한다.
4. WHEN 둘 이상의 판례가 동일한 검색_우선순위를 가지면, THE Python_기준_구현 SHALL 목업_데이터_레코드에 사전 정의된 동순위 순서로 판례를 반환한다.
5. WHEN 동일한 상황_질의와 동일한 목업_데이터셋으로 목업_검색을 반복하면, THE Python_기준_구현 SHALL 동일한 유사도_점수, 검색_우선순위 및 동순위 순서를 반환한다.
6. WHEN 클라이언트_웹_계층이 판례 결과를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 유사도_점수와 판례 순서를 재계산 또는 재정렬하지 않고 표시한다.
7. THE 클라이언트_웹_계층 SHALL 결과 화면에 유사도 요소와 최신성 요소가 검색_우선순위에 반영된 목업 값임을 설명한다.
8. THE 클라이언트_웹_계층 SHALL 결과 화면에 `유사도 점수와 검색 순서는 사전 정의된 목업 값이며, 현재 시연에서는 실제 운영 환경의 산식이나 판례 적합성·정확성을 보증하지 않습니다.`라는 문구를 표시한다.
9. THE 클라이언트_웹_계층 SHALL 각 판례 결과에 Python_기준_구현이 반환한 해당_심급_인정_죄명과 해당_심급_재판_결과를 표시한다.
10. IF 해당_심급_인정_죄명 또는 해당_심급_재판_결과가 목업_데이터_레코드에 없으면, THEN THE Python_기준_구현 SHALL 누락된 값을 `확인되지 않음`으로 반환한다.
11. IF 판례 레코드의 유사도_점수가 누락되거나 숫자가 아니거나 0 미만이거나 100을 초과하면, THEN THE Python_기준_구현 SHALL 해당 판례 레코드에만 레코드_격리를 적용하고 `유사도 데이터 오류`를 반환한다.
12. IF 판례 레코드의 검색_우선순위 또는 동순위 순서가 누락되거나 목업_데이터셋에 사전 정의된 순서 값 형식을 충족하지 않으면, THEN THE Python_기준_구현 SHALL 해당 판례 레코드에만 레코드_격리를 적용하고 `검색 순서 데이터 오류`를 반환한다.
13. WHILE 하나 이상의 판례 레코드가 레코드_격리된 상태에서, THE Python_기준_구현 SHALL 나머지 유효한 판례 레코드의 사전 정의 유사도_점수와 순서를 유지한다.

### 요구사항 8: 핵심 사실관계 차이와 유사도 경고

**사용자 스토리:** 경찰 실무자로서, 높은 유사도 숫자만 보지 않고 내 상황과 판례의 결정적 차이를 알고 싶다. 이를 통해 판례 결론을 그대로 적용하는 오류를 줄일 수 있다.

#### 인수 기준

1. WHEN 판례 결과가 생성되면, THE Python_기준_구현 SHALL 상황_질의와 판례 사이의 핵심_사실관계_차이를 판례 결과와 분리된 구조로 반환한다.
2. THE Python_기준_구현 SHALL 각 핵심_사실관계_차이를 사용자 사실, 판례 사실 및 결론 영향의 세 요소로 구성한다.
3. THE Python_기준_구현 SHALL 체포 시점, 영장 유무, 동행 자발성, 권리 고지 여부, 물리력 정도 및 증거 확보 방식 중 목업_데이터_레코드에 사전 정의된 비교 항목을 반환한다.
4. IF 비교에 필요한 사용자 사실이 상황_질의에 없으면, THEN THE Python_기준_구현 SHALL 사용자 사실을 `확인 필요`로 반환한다.
5. IF 비교에 필요한 판례 사실이 목업_출처에 없으면, THEN THE Python_기준_구현 SHALL 판례 사실을 `확인 필요`로 반환한다.
6. IF 핵심_사실관계_차이의 결론 영향이 목업_데이터_레코드에 없으면, THEN THE Python_기준_구현 SHALL 결론 영향을 `확인 필요`로 반환한다.
7. WHEN 유사도_점수가 80 이상 100 이하이면, THE Python_기준_구현 SHALL `높은 유사도 — 핵심 차이 확인 필요`라는 유사도_경고를 반환한다.
8. WHEN 유사도_점수가 50 이상 80 미만이면, THE Python_기준_구현 SHALL `중간 유사도 — 직접 적용 전 사실관계 재검토 필요`라는 유사도_경고를 반환한다.
9. WHEN 유사도_점수가 0 이상 50 미만이면, THE Python_기준_구현 SHALL `낮은 유사도 — 결론 근거로 사용 금지`라는 유사도_경고를 반환한다.
10. WHEN 판례에 결론을 바꿀 수 있는 핵심_사실관계_차이가 존재하면, THE Python_기준_구현 SHALL 해당 차이를 유사도_점수보다 앞선 경고 항목으로 반환한다.
11. THE Python_기준_구현 SHALL 적법성_상태, 법원_결론 및 해당_심급_재판_결과를 유사도_점수와 독립적으로 해당 판례의 목업_데이터_레코드에서 결정한다.
12. WHEN 명시적 시점이 있는 동일한 핵심 사실 집합의 문장 순서만 변경되면, THE Python_기준_구현 SHALL 동일한 판례 집합과 유사도_점수를 반환한다.
13. WHEN 클라이언트_웹_계층이 핵심_사실관계_차이와 유사도_경고를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 세 요소, 경고 구간 및 항목 순서를 변경 없이 표시한다.

### 요구사항 9: 선택 영역 사실 확인과 상세 설명

**사용자 스토리:** 경찰 실무자로서, 답변 전체가 아니라 이해가 필요하거나 의심되는 부분만 선택하여 다시 확인하고 싶다. 이를 통해 근거를 효율적으로 검토할 수 있다.

#### 인수 기준

1. WHEN 사용자가 목업_응답의 텍스트를 드래그하여 유효한_선택_영역을 만들면, THE 클라이언트_웹_계층 SHALL `사실 확인 재검토`와 `상세 설명` 작업을 제공한다.
2. WHEN 사용자가 목업_응답의 유효한_선택_영역에 대한 문맥 메뉴를 열면, THE 클라이언트_웹_계층 SHALL `사실 확인 재검토`와 `상세 설명` 작업을 제공한다.
3. WHEN 사용자가 선택_재검토를 요청하면, THE Python_웹_서버 SHALL 선택 영역이 현재 목업_응답 안의 유효한_선택_영역인지 검증한다.
4. IF 선택 영역이 공백 문자로만 구성되거나 현재 목업_응답 범위 밖에 있으면, THEN THE Python_기준_구현 SHALL 선택_재검토 상태를 선택 대기로 유지한다.
5. WHILE 선택 영역이 유효한_선택_영역이 아닌 상태에서, THE Python_기준_구현 SHALL 재검토 결과를 빈 집합으로 유지한다.
6. WHEN 선택_재검토 상태가 선택 대기로 유지되면, THE 클라이언트_웹_계층 SHALL 텍스트 선택 안내를 표시한다.
7. WHEN 유효한_선택_영역에 하나 이상의 독립_주장이 포함되면, THE Python_기준_구현 SHALL 각 독립_주장을 재검토 결과에 정확히 한 번 반환한다.
8. WHEN 사용자가 사실 확인 재검토를 실행하면, THE Python_기준_구현 SHALL 각 독립_주장을 근거_일치, 근거_충돌 또는 근거_부족 중 정확히 하나의 근거_상태로 판정한다.
9. WHEN 하나 이상의 결정_근거가 독립_주장의 전체 내용을 직접 뒷받침하고 독립_주장과 충돌하는 결정_근거가 없으면, THE Python_기준_구현 SHALL 독립_주장의 근거_상태를 근거_일치로 판정한다.
10. IF 하나 이상의 결정_근거가 독립_주장과 충돌하면, THEN THE Python_기준_구현 SHALL 독립_주장의 근거_상태를 근거_충돌로 판정한다.
11. IF 독립_주장과 충돌하는 결정_근거가 없고 독립_주장의 전체 내용을 직접 뒷받침하는 결정_근거도 없으면, THEN THE Python_기준_구현 SHALL 독립_주장의 근거_상태를 근거_부족으로 판정한다.
12. WHEN 독립_주장의 근거_상태가 근거_일치 또는 근거_충돌이면, THE Python_기준_구현 SHALL 근거_상태를 결정한 각 결정_근거의 출처_식별자를 반환한다.
13. IF 결정_근거는 없고 선택 문구와 주제가 관련된 목업_출처만 있으면, THEN THE Python_기준_구현 SHALL 관련 목업_출처를 결정_근거와 분리된 참고_출처로 반환한다.
14. WHEN 사용자가 상세 설명을 실행하면, THE Python_기준_구현 SHALL 선택 문구의 법률 용어, 문맥 및 판례_쟁점을 구분하여 반환한다.
15. IF 선택 문구의 의미를 목업_데이터셋에서 확인할 수 없으면, THEN THE Python_기준_구현 SHALL `목업 자료에서 확인할 수 없음` 문구와 목업_데이터_레코드에 사전 정의된 추가 필요 정보를 반환한다.
16. WHEN 클라이언트_웹_계층이 선택_재검토 결과를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 독립_주장, 근거_상태, 결정_근거 및 참고_출처를 변경 없이 구분하여 표시한다.
17. WHEN 사용자가 재검토 결과의 출처_식별자를 선택하면, THE 클라이언트_웹_계층 SHALL 선택 문구와 직접 관련된 근거 구절의 위치로 이동하여 근거 구절을 강조한다.

### 요구사항 10: 최신 판례와 현행 법령 기준 표시

**사용자 스토리:** 경찰 실무자로서, 현재 적용되는 법령 기준의 판례를 먼저 확인하고 싶다. 이를 통해 구법에 기초한 판례를 현행 기준으로 오인하지 않을 수 있다.

#### 인수 기준

1. THE Python_기준_구현 SHALL 판례가 인용한 각 법조문을 법령명과 조·항·호를 포함하는 고유 법조문 태그로 정확히 한 번 반환한다.
2. WHEN 법조문 레코드에 최신 개정일과 시행일이 존재하면, THE Python_기준_구현 SHALL 각 법조문 태그에 최신 개정일과 시행일을 반환한다.
3. IF 법조문 레코드에 최신 개정일 또는 시행일이 없으면, THEN THE Python_기준_구현 SHALL 누락된 날짜 필드를 정보_없음으로 반환한다.
4. WHEN 판례 결과가 생성되면, THE Python_기준_구현 SHALL 판결 선고일과 인용 법조문의 개정일 및 시행일을 동일한 법령 상태 구조로 반환한다.
5. THE Python_기준_구현 SHALL 각 판례의 법령_기준_상태를 현행법_기준, 구법_기준 또는 법령_상태_판별불가 중 정확히 하나로 판정한다.
6. WHEN 판례가 적용한 모든 법조문 버전이 데이터_기준일의 현행_법령 버전과 같으면, THE Python_기준_구현 SHALL 판례의 법령_기준_상태를 현행법_기준으로 판정한다.
7. WHEN 판례가 적용한 모든 법조문 버전을 판별할 수 있고 하나 이상의 적용 버전이 데이터_기준일의 현행_법령보다 이전이면, THE Python_기준_구현 SHALL 판례의 법령_기준_상태를 구법_기준으로 판정한다.
8. IF 법령 버전 판별에 필요한 개정일, 시행일 또는 적용 버전이 없거나 적용 버전을 비교할 수 없으면, THEN THE Python_기준_구현 SHALL 누락된 날짜를 추론하지 않고 판례의 법령_기준_상태를 법령_상태_판별불가로 판정한다.
9. WHEN 검색 결과에 현행법_기준 판례와 구법_기준 판례가 함께 존재하면, THE Python_기준_구현 SHALL 목업_데이터_레코드에 사전 정의된 검색_우선순위를 적용하여 모든 현행법_기준 판례를 구법_기준 판례보다 앞에 반환한다.
10. WHEN 구법_기준 판례가 표시되면, THE 클라이언트_웹_계층 SHALL `구법 기준` 배지와 Python_기준_구현이 반환한 관련 법조문의 개정 내용을 표시한다.
11. IF 판례의 법령_기준_상태가 법령_상태_판별불가이면, THEN THE 클라이언트_웹_계층 SHALL `법령 상태 판별 불가` 배지를 표시한다.
12. THE 클라이언트_웹_계층 SHALL 판례와 법령의 최신성이 데이터_기준일에 고정된 목업 정보임을 법령 상태 영역에 표시한다.
13. WHEN 동일한 법령_기준_상태의 판례를 정렬하면, THE Python_기준_구현 SHALL 목업_데이터_레코드에 사전 정의된 검색_우선순위를 적용한다.
14. WHEN 클라이언트_웹_계층이 법령_기준_상태와 판례 목록을 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 상태와 현행법 우선 순서를 재판정 또는 재정렬하지 않고 표시한다.

### 요구사항 11: 사실관계 타임라인과 보고서 재사용

**사용자 스토리:** 경찰 실무자로서, 사전 정의 음성 시연이나 뒤섞인 자연어로 설명된 사건을 시간 순서로 정리하고 싶다. 이를 통해 각 행위의 법적 쟁점을 확인하고 보고서 사실관계 작성에 재사용할 수 있다.

#### 인수 기준

1. THE 경찰_판례_AI_봇 SHALL 음성 입력 시연을 사전_정의_음성_시연으로 제공한다.
2. THE 경찰_판례_AI_봇 SHALL 실제_음성_인식과 원격 음성 인식 서비스 호출 수를 각각 0건으로 유지한다.
3. WHEN 사용자가 사전_정의_음성_시연 항목을 선택하면, THE Python_기준_구현 SHALL 목업_데이터_레코드에 사전 정의된 인식 텍스트를 반환한다.
4. WHEN 사용자가 시간 순서가 뒤섞인 지원_목업_질의를 제출하면, THE Python_기준_구현 SHALL 목업_데이터_레코드에 사전 정의된 인식_사건으로 사실관계_타임라인을 구성한다.
5. THE Python_기준_구현 SHALL 명시적 날짜와 시간이 있는 인식_사건을 날짜와 시간의 오름차순으로 배열한다.
6. WHEN 상대적 시간 표현에 기준 시점이 존재하면, THE Python_기준_구현 SHALL 상대적 시간 표현에 해당하는 인식_사건을 기준 시점에 따라 배열한다.
7. WHEN 둘 이상의 인식_사건이 동일한 시점을 가지면, THE Python_기준_구현 SHALL 사용자 설명에 나타난 행위 순서를 유지한다.
8. IF 인식_사건의 시점을 판단할 수 없으면, THEN THE Python_기준_구현 SHALL 인식_사건을 원래 표현과 함께 `시점 미상` 집합으로 반환한다.
9. THE Python_기준_구현 SHALL 지원_목업_질의에서 식별한 각 인식_사건을 사실관계_타임라인에 정확히 한 번 배치한다.
10. THE Python_기준_구현 SHALL 사실관계_타임라인의 각 인식_사건에 하나 이상의 판례_쟁점 또는 `연결 쟁점 없음` 상태를 연결한다.
11. WHEN 인식_사건에 판례_쟁점이 연결되면, THE Python_기준_구현 SHALL 판례_쟁점에 사전 연결된 판례 및 법조문의 출처_식별자를 반환한다.
12. IF 시간 표현 또는 행위 주체를 둘 이상의 방식으로 해석할 수 있으면, THEN THE Python_기준_구현 SHALL 원래 표현과 복수의 해석 가능성을 유지하고 인식_사건을 `사용자 확인 필요`로 반환한다.
13. WHEN 사용자가 인식_사건의 시간 또는 내용을 수정하면, THE Python_기준_구현 SHALL 기존 값을 수정된 값으로 교체하여 사실관계_타임라인과 보고서용_사실관계에 함께 반영한다.
14. WHEN 사용자가 보고서용_사실관계 생성을 요청하면, THE Python_기준_구현 SHALL 사실관계_타임라인의 각 인식_사건을 사실관계_타임라인 순서대로 정확히 한 번 포함한 보고서용_사실관계를 반환한다.
15. WHEN 클라이언트_웹_계층이 보고서용_사실관계를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 본문을 변경 없이 복사와 파일 다운로드에 사용할 수 있게 제공한다.
16. WHEN 보고서용_사실관계가 복사되거나 파일로 다운로드되면, THE 클라이언트_웹_계층 SHALL 데이터_기준일과 법률_안전_고지문을 본문과 함께 제공한다.
17. IF 보고서용_사실관계의 복사 또는 파일 다운로드가 실패하면, THEN THE 클라이언트_웹_계층 SHALL 현재 보고서용_사실관계 본문과 사실관계_타임라인을 화면에 유지하고 실패 안내를 표시한다.
18. IF 선택한 사전_정의_음성_시연 항목에 인식 텍스트가 없으면, THEN THE Python_기준_구현 SHALL 목업_RAG_단계를 입력 상태로 유지한다.
19. WHEN 선택한 사전_정의_음성_시연 항목에 인식 텍스트가 없어 목업_RAG_단계가 입력 상태로 유지되면, THE 클라이언트_웹_계층 SHALL 수동 텍스트 입력 수단을 제공한다.
20. WHEN 클라이언트_웹_계층이 사전_정의_음성_시연의 인식 텍스트를 수신하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 인식 텍스트를 변경 없이 표시한다.

### 요구사항 12: 전체 판례 범위와 심급·상급심·확정 정보

**사용자 스토리:** 경찰 실무자로서, 공개적으로 확인 가능한 제1심·항소심·상고심 판례를 폭넓게 참고하고, 각 판례의 심급·상급심 판단·확정 여부를 확인하고 싶다. 이를 통해 개별 판결을 최종 결론으로 오인하지 않고, 사건과 유사한 사실관계 및 최신 상급심 판단을 함께 검토할 수 있다.

#### 인수 기준

1. THE 클라이언트_웹_계층 SHALL 목표 데이터 범위를 `공개적으로 확인 가능한 제1심·항소심·상고심 판례`로 표시한다.
2. THE 클라이언트_웹_계층 SHALL 현재 구현 데이터 범위를 `사전에 정의된 목업 전체 심급 판례 샘플`로 표시한다.
3. WHEN 목표 데이터 범위와 현재 구현 데이터 범위가 표시되면, THE 클라이언트_웹_계층 SHALL 두 범위를 서로 구분된 항목으로 표시한다.
4. THE 클라이언트_웹_계층 SHALL 모든 판례 목록과 상세 화면에 `판례는 심급 및 절차 경과에 따라 결론이 달라질 수 있으므로, 상급심 판단과 확정 여부를 함께 확인해야 합니다.`라는 고정 안내를 표시한다.
5. THE Python_기준_구현 SHALL 각 판례 결과에 법원명, 심급, 사건번호, 선고일 및 해당_심급_재판_결과를 반환한다.
6. WHEN 목업_데이터셋에 항소 또는 상고 정보가 있으면, THE Python_기준_구현 SHALL 상급심 사건번호, 심급, 선고일 및 결과를 반환한다.
7. WHEN 목업_데이터셋에 확정 정보가 있으면, THE Python_기준_구현 SHALL 확정_여부를 확정 또는 미확정으로 반환한다.
8. IF 항소 또는 상고 정보가 목업_데이터셋에 없으면, THEN THE Python_기준_구현 SHALL 상급심_정보를 정보_없음으로 반환한다.
9. IF 확정 정보가 목업_데이터셋에 없으면, THEN THE Python_기준_구현 SHALL 확정_여부를 정보_없음으로 반환한다.
10. WHEN 상급심이 1심 결과를 변경한 판례가 표시되면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 1심 결과와 상급심 결과의 차이를 강조한다.
11. WHILE 상급심_정보가 정보_없음인 상태에서, THE Python_기준_구현 SHALL 상급심 사건번호, 심급, 선고일 및 결과를 정보_없음으로 유지한다.
12. WHILE 상급심_정보 또는 확정_여부가 정보_없음인 상태에서, THE Python_기준_구현 SHALL 목업_데이터_레코드에 없는 상급심 값 또는 확정 상태의 추론 건수를 0건으로 유지한다.
13. WHILE 확정_여부가 정보_없음인 상태에서, THE 클라이언트_웹_계층 SHALL 확정 또는 미확정 배지의 표시 건수를 0건으로 유지한다.
14. WHEN 클라이언트_웹_계층이 1심, 상급심 및 확정 정보를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 값과 정보_없음 상태를 변경 없이 표시한다.
15. WHEN 클라이언트_웹_계층이 판례 결과 목록 카드를 표시하면, THE 클라이언트_웹_계층 SHALL Python_기준_구현이 반환한 상급심_정보 요약과 확정_여부를 각 목록 카드에 변경 없이 표시한다.
16. IF 목록 카드의 상급심_정보가 정보_없음이면, THEN THE 클라이언트_웹_계층 SHALL 해당 목록 카드에 상급심_정보를 정보_없음 상태로 표시한다.
17. WHILE 목록 카드의 확정_여부가 정보_없음인 상태에서, THE 클라이언트_웹_계층 SHALL 해당 목록 카드의 확정 또는 미확정 배지 표시 건수를 0건으로 유지한다.

### 요구사항 13: 결과 추적성, 일관성 및 안전한 실패

**사용자 스토리:** 시연 검증자로서, 표시된 값이 사전 정의 데이터와 일치하고 오류 상황에서 근거 없는 법률 결론이 나오지 않기를 원한다. 이를 통해 목업 동작을 반복 가능하게 검증할 수 있다.

#### 인수 기준

8. WHEN 브라우저_세션이 종료되면, THE 경찰_판례_AI_봇 SHALL 종료된 브라우저_세션의 민감_사용자_콘텐츠를 새 브라우저_세션에 복구한 건수를 0건으로 유지한다.
9. WHEN Python_웹_서버가 재시작되면, THE Python_웹_서버 SHALL 재시작 전 민감_사용자_콘텐츠를 영구_저장 상태에서 복구한 건수를 0건으로 유지한다.

### 요구사항 18: HTTP 및 서버 오류의 안전한 처리

**사용자 스토리:** 사용자 및 운영 검증자로서, 잘못된 웹 요청이나 서버·데이터 오류가 발생해도 근거 없는 법률 결과 대신 안전한 오류 안내를 받고 싶다. 이를 통해 웹 배포 환경의 실패를 법률 결론으로 오인하지 않을 수 있다.

#### 인수 기준

1. IF 경찰_판례_AI_봇에 정의된 URL로 전송된 HTTP 요청의 메서드와 콘텐츠 유형이 지원되지만 요청 구문, 필수 필드 구조 또는 필드 값 유형이 정의된 입력 형식을 충족하지 않으면, THEN THE Python_웹_서버 SHALL HTTP 400 상태의 안전_오류_응답을 반환한다.
2. IF 경찰_판례_AI_봇에 정의된 URL로 전송된 HTTP 요청의 메서드가 지원되지 않으면, THEN THE Python_웹_서버 SHALL HTTP 405 상태의 안전_오류_응답을 반환한다.
3. IF 경찰_판례_AI_봇에 정의된 URL로 전송된 HTTP 요청의 메서드는 지원되지만 콘텐츠 유형이 지원되지 않으면, THEN THE Python_웹_서버 SHALL HTTP 415 상태의 안전_오류_응답을 반환한다.
4. IF 요청 URL이 경찰_판례_AI_봇에 정의되지 않으면, THEN THE Python_웹_서버 SHALL HTTP 404 상태의 안전_오류_응답을 반환한다.
5. IF 유효한 HTTP 요청 처리 중 처리되지 않은 서버 오류가 발생하면, THEN THE Python_웹_서버 SHALL HTTP 500 상태의 안전_오류_응답을 반환한다.
6. IF Python_웹_서버 시작 또는 재시작 중 데이터셋_가용성_실패가 발생하고 유효한 HTTP 요청이 정의된 URL로 전송되면, THEN THE Python_웹_서버 SHALL 목업_RAG 실행을 차단하고 HTTP 503 상태의 안전_오류_응답을 반환한다.
7. WHILE 데이터셋_가용성_실패가 해결되지 않은 상태에서, THE Python_웹_서버 SHALL 법률 결론, 매칭_결과_집합 및 보고서용_사실관계의 반환 건수를 각각 0건으로 유지한다.
8. WHEN Python_웹_서버가 안전_오류_응답을 반환하면, THE Python_웹_서버 SHALL 내부 예외 상세, 비밀값, 민감_사용자_콘텐츠 및 목업_데이터_레코드에 없는 대체 법률 결론의 포함 건수를 각각 0건으로 유지한다.
9. WHEN Python_웹_서버가 안전_오류_응답을 반환하면, THE Python_웹_서버 SHALL 재시도 가능 여부를 가능 또는 불가능 중 정확히 하나로 명시한다.
10. IF HTTP_클라이언트_오류 또는 HTTP_서버_오류가 재시도 가능한 상태이면, THEN THE Python_웹_서버 SHALL 안전_오류_응답에 재시도 작업을 포함한다.
11. WHEN 클라이언트_웹_계층이 안전_오류_응답을 표시하면, THE 클라이언트_웹_계층 SHALL Python_웹_서버가 반환한 HTTP 상태, 일반화된 오류 안내 및 재시도 가능 여부를 변경 없이 표시한다.
12. WHEN 안전_오류_응답이 표시되면, THE 클라이언트_웹_계층 SHALL 공개_배포_고지문, 법률_안전_고지문, 개인정보_처리_고지문 및 진입_화면 이동 수단을 함께 제공한다.
